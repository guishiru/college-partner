# 0002 统计方法黄金基线

## 状态

已采纳。

## 背景

改造身份层时发现，现有的 `tests/test_statistical_engine.py` 只断言形状：结果回来了、有表、meta 里写着方法名和版本号。这类断言有一个共同的盲区——**统计错误不抛异常**。分母写错、自由度差一、静默丢掉一行样本、把 Pearson 算成 Spearman，这些都会返回一个数值合理、结构完整的结果，现有测试全部通过。

`testing.md` 里本来就写着「每个方法必须有固定样例数据和可核对的基准结果」，但没有实现。

## 决定

新增 `tests/golden/`，用一份固定数据集把 11 个方法的实际输出固化为基线文件，每次运行逐值比对。

**数据集是夹具，不是测试数据。** `baseline_survey.csv` 提交进仓库，180 行 18 列，包含三个维度各 4 个李克特题项、一组连续变量（自变量、调节变量、两个中介、因变量）和一个分类变量，足以覆盖全部 11 个方法。它的 SHA-256 记录在 `cases.py` 中并由测试校验——改数据会让所有基线同时失去意义，而且**基线仍然会对新数据比对成功**，这是最危险的一种假绿灯，所以必须让它变成显式报错。

**基线包含 `display`。** 最初的版本只固化了 `meta` 和结果表，验证时发现一个典型的 off-by-one（残差自由度 `n-k-1` 改成 `n-k`）能完整通过。原因是线性回归的模型汇总行——R²、调整 R²、F 值、残差自由度、p 值——只存在于 `display.tables.regression_table.model_summary_row` 这个预渲染字符串里，结构化结果中没有。这暴露出一个值得后续处理的设计问题：**用户实际读到的统计量以文本形式存在，报告模块无法程序化引用，只能解析字符串或自行重算**。本次先把它纳入基线覆盖，设计问题另案处理。

**长表只存摘要。** 因子得分表、综合得分表这类按样本逐行输出的表有 180 行，全量固化让 EFA 的基线达到 122 KB，diff 完全不可读。超过 30 行的表改为记录列名、行数、头尾各 3 行，以及每个数值列的 count/sum/min/max。这些表都由载荷、特征根等参数派生，而参数本身是逐值固化的；头尾行提供诊断线索，列聚合保证中间行的改动无处可藏。EFA 基线因此降到 30 KB。

**容差取相对 1e-6。** 足以容忍不同 BLAS 实现的浮点末位差异，任何真实的公式改动都远大于这个量级。

**重新生成必须是显式动作。** `regenerate.py` 是独立命令，测试失败时不会自动更新基线。会自动更新的基线什么都证明不了——它会把每一次回归变成一次绿灯加一份没人看的 diff。

## 顺带修正

`AnalysisEngine.run` 现在把调用期间抛出的 `ImportError` 统一包装成 `AnalysisDependencyError`。此前 SEM 在模块导入时报缺依赖，被 `_load_function` 正确识别；CFA 在函数内部导入，同样的缺依赖却落进通用异常分支变成 `AnalysisEngineError`。同一个原因抛两种类型，调用方无法区分「依赖没装」和「数据有问题」。

`modules/analysis/engine/__init__.py` 补充导出 `AnalysisDependencyError`。

## 有效性验证

基线抓不到东西就等于没做。以下五种改动逐一注入并确认测试变红，随后还原：

| 注入的改动 | 是否被抓到 |
|---|---|
| 回归残差自由度 `n-k-1` → `n-k` | 是（`display` 中 F(3,176) → F(3,177)） |
| 标准差 `ddof=1` → `ddof=0` | 是（Beta 0.33629 → 0.33723） |
| 信度分析静默丢掉一行样本 | 是（样本量 180 → 179，α 0.86571 → 0.86659） |
| 相关分析 Pearson → Spearman | 是（口径字段与全部相关系数） |
| 篡改黄金数据集本身 | 是（SHA-256 校验失败） |

## 基线抓到的第一个真实缺陷：CFA 因子协方差表不可复现

补齐 `cfa` 基线后立刻变红，而同一进程内连跑两次又完全一致。原因是 `semopy` 以无序对的形式返回因子间协方差，行顺序和 A↔B / B↔A 的朝向都跟着 `PYTHONHASHSEED` 走：

```
HASHSEED=1  [('维度A','维度B'), ('维度C','维度A'), ('维度C','维度B')]
HASHSEED=2  [('维度A','维度B'), ('维度A','维度C'), ('维度C','维度B')]
HASHSEED=3  [('维度B','维度A'), ('维度C','维度A'), ('维度C','维度B')]
```

统计量完全相同——协方差本身对称——但**同一份数据每次生成的报告长得不一样**。这类缺陷在进程内重跑测不出来，只有跨进程的固化基线能发现。

已在 CFA 方法内归一化：每对因子按字典序把小的放在前列，再按变量名排序。只改呈现，不改任何数值。

```
pip install "setuptools<60" wheel
pip install --no-build-isolation semopy
```
