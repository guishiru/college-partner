# 0006 语义识别：关键词优先，大模型兜底，置信度闸门

## 状态

已采纳。识别层已接通（千问适配器 + 假客户端）；文档撰写类的生成接入尚未做。

## 背景

在此之前，整个代码库**没有一行大模型调用**。需求识别是一张关键词表加正则：

```python
"reliability": {"keywords": ["信度", "可靠性", "Cronbach", "Alpha", "α"], ...}
```

实测代价很具体：

| 用户可能怎么说 | 关键词表 |
|---|---|
| 做信度分析，题项是 社会支持1、2、3 | 识别出 |
| 帮我算下 Cronbach | 识别出 |
| 看看社会支持这几道题一不一致 | **识别不出** |
| 这三道题内部一致性怎么样 | **识别不出** |
| 社会支持和主观规范有没有关系 | **识别不出** |

后三句是人正常会说的话。用户必须学会说「信度分析」这四个字才能用产品。

项目约定写着「大模型只能负责需求解析、参数补全、追问和文字解释，不能直接计算统计量」——当时的状况是下半句执行得很彻底，上半句根本没实现。

## 决定

**关键词表保留，作为快路径。** 命中的时候它比模型又快又准又免费，结果还稳定。为「做信度分析」这种毫无歧义的说法调一次模型，是白花钱，还凭空引入一个不确定性来源。有一条测试盯着这点：关键词命中时模型调用次数必须为 0。

**兜不住才调模型，模型只做翻译。** 它把人话翻成方法标识和变量名，引擎、口径、黄金基线、拒绝条件一律不动。

**置信度决定动作：**

| 置信度 | 动作 |
|---|---|
| ≥ 0.75 | 直接按模型的判断执行 |
| 0.45 – 0.75 | 带着猜测追问：「你是想做信度分析吗？」 |
| < 0.45 | 不带猜测，走原来的追问 |

中间档是这次设计里最划算的一处：模型有个像样的猜测时，带着猜测问比干问一句「请确认要做哪一种统计分析」省用户一轮，猜错了用户一句话也能纠正。

## 模型的笼子

模型的输出在进入引擎前过四道校验，任何一条不过，整条结果作废、退回追问：

1. **方法必须是引擎支持的 11 个之一**——编一个「聚类分析」，退回。
2. **列名必须在数据里真实存在**——杜撰变量，退回。
3. **引用的原文片段必须真的出现在用户输入里**——要求模型说出它据以判断的原话，那句话不在输入里就说明它在编。
4. **置信度必须是 0 到 1 的数**。

第 3 条最管用，而且几乎零成本。模型编造依据时，编出来的句子通常不在原文里。

另加一道降权：模型自报的把握不能全信，如果用户原话里连一个跟该方法沾边的字都没有，置信度打七折。

**这些不是纸面约定，是一组对抗测试。** `AdversarialModelTests` 逐一喂进不存在的方法、杜撰的列名、伪造的引用、超范围的置信度、非 JSON、半截 JSON、调用异常，要求结果一律是退回追问。同时有一条反向用例：模型爱加代码块标记和客套话，这个不算越界，必须能容忍。

## 关键取舍

**没配置模型时明确报错，不静默降级。** `NullClient` 被调用会抛 `LLMNotConfigured`，识别层把它记成「未配置模型」。「模型没配置」和「模型识别不出」是两件事，混在一起会让线上出问题时查不出原因。

**接口只有一个方法**：消息进，文本出。不暴露流式、函数调用、多模态——用得上再说。接口越窄，换厂商越便宜。

**千问走 DashScope 的 OpenAI 兼容端点，用标准库发请求。** 这里只需要一次 POST 和一次 JSON 解析，为此拉一个 SDK 进来不划算。换厂商通常只改 `LLM_BASE_URL` 和 `LLM_MODEL`。

**假客户端不是将就。** 要验的是「模型乱说时系统会不会被污染」，这就必须能精确控制模型说什么。真调 API 的测试慢、贵、每次结果不一样，CI 里根本跑不了。

**token 用量随识别结果返回。** 现在还没接计费，但字段先留着——以后要算账不用回头改表。

## 密钥

只从环境变量读，不落盘、不进日志、不进异常消息。`.env.example` 说明要配哪些变量，`.env` 本身在 `.gitignore` 里。

## 模块边界

新增叶子模块 `modules/llm`，不依赖任何业务模块。

`modules/skills` 获准依赖 `modules.llm`——语言层的职责本就是把人话翻译成方法和参数。**引擎依然不许**，那条测试（`test_the_engine_never_imports_an_llm_or_the_language_layer`）原封不动。
