# 0003 布局归属虚拟员工，分析结果可回看

## 状态

已采纳。

## 背景

两个问题都出在同一处：界面把「数据分析师此刻的样子」当成了产品的形状。

**一、布局被写死成全局设定。** 侧栏的三个虚拟员工是硬编码的 HTML，工作区固定两栏。但两栏是数据分析师的需求——统计表宽，而且用户要一边看结果一边提下一个需求。写 PRD 产出的是一份正在成形的文档，形态不同；职场陪跑的回答基本是成段文字，第二栏会一直空着。六个员工都上线后再统一，代价是六处界面各改一遍。

**二、只有最新一次分析可达。** `renderResults` 每次直接覆盖 `innerHTML`，同一会话里前面几次分析的结果和报告在界面上再也找不回来。数据其实都在——Job 记录、落盘的结果 JSON、报告文件一个不少——缺的只是一个入口。

## 决定

**布局是虚拟员工的属性。** 把此前只有 `.gitkeep` 的 `modules/employees` 实现出来，员工声明自己的身份、可用 Skill、可召唤对象和 `layout`。前端从 `/api/employees` 取清单渲染侧栏，工作区按当前员工的 `layout` 渲染。

三种布局：`analysis_split`（对话 + 结果工作区）、`document_split`（对话 + 文档）、`conversation`（纯对话）。当前只有数据分析师开放，但另外两种布局的取值、样式分支和测试都已存在——否则这个字段等于没有。

**注册表先放在代码里。** 产品总纲把员工配置划给管理员，最终要可存储可编辑。但在第二个员工真正能用之前，建一张数据库表只是给一个常量套仪式。关键是其余模块通过这个模块的接口读员工，而不是各自硬编码；以后换存储只动这一个文件。

**结果回看走任务，不走界面缓存。** 新增 `GET /api/jobs/<session_id>/<job_id>/result`，读回任务落盘的完整结果。右侧加会话内分析历史，点一条就把结果和报告链接一起切回去。把权威数据放在服务端而不是浏览器内存，意味着刷新页面、换设备继续，历史都还在。

## 关键取舍

**会话开始后不允许换员工。** 会话在创建时绑定员工，中途切换会牵出「之前的任务算谁的」「文件归属怎么迁移」一连串问题。当前直接拒绝并提示新建会话。

**未开放的员工不得声明 Skill。** 有一条测试盯着这点。否则注册表会慢慢变成愿望清单，而界面无从分辨哪些员工真能干活。

**`/api/employees` 不需要鉴权。** 它只返回员工的公开描述，不含任何用户数据，而未登录的页面需要它来渲染侧栏。

## 影响

- 新增 `modules/employees`，叶子模块，不依赖任何其他模块。
- 新增 `GET /api/employees`；`POST /api/sessions` 接受 `employee` 并返回该员工完整属性。
- 新增 `GET /api/jobs/<session_id>/<job_id>/result`。
- 前端侧栏、工作区布局、结果历史改为数据驱动。
- 端到端测试增加一段：做两次不同分析，从历史切回第一次，确认结果和报告都跟着切回去，且重复的相同请求不会在历史里多出一条。

## 待办

`document_split` 和 `conversation` 目前只有声明和渲染分支，没有真正的内容。做报告撰写专家时补 `document_split` 的文档栏。
