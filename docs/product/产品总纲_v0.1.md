# 产品总纲 v0.1

## 文档状态

- 版本：v0.1
- 状态：初始基线
- 适用范围：虚拟员工与多 Skill 工作应用
- 本文只规定产品边界、业务对象、权限和数据流，不规定具体技术实现。

## 1. 产品定位

这是一个面向多个用户使用的虚拟员工工作台。

用户通过选择虚拟员工进入工作场景，由该员工自动使用已经配置好的一个或多个 Skill 完成任务。用户不需要先判断意图，也不需要理解复杂的功能分类。

虚拟员工是产品中的工作身份和能力入口，不是独立用户。一个任务可以由当前虚拟员工完成，也可以在对话过程中召唤另一个虚拟员工协作。

## 2. 产品基本形态

- 左侧：虚拟员工列表。
- 右侧：当前虚拟员工的对话和工作区。
- 对话中可以上传文件、查看任务状态、查看结果和下载文件。
- 当前虚拟员工默认负责当前任务，并可以调用允许协作的其他虚拟员工。
- 用户的数据、会话、任务和结果必须相互隔离。

## 3. 模块边界

### 3.1 用户与权限模块

负责用户身份、登录状态、用户状态和用户可访问范围。

不负责：虚拟员工的业务能力、数据分析规则和报告内容。

### 3.2 虚拟员工模块

负责虚拟员工的身份、名称、描述、适用场景、可使用 Skill 和可召唤员工。

不负责：具体分析方法的实现、用户文件的长期管理和对话内容生成。

### 3.3 Skill 与方法模块

负责可复用的业务能力和方法定义，例如数据读取、数据清洗、描述统计、显著性检验、回归分析、简历修改等。

Skill 可以被多个虚拟员工使用。数据分析类 Skill 的统计口径以 SPSS 的常用业务口径为基准，具体口径在对应模块 PRD 中定义。

不负责：决定用户当前选择哪个虚拟员工，也不负责跨用户数据访问。

### 3.4 会话与消息模块

负责用户与虚拟员工之间的会话、消息、当前员工身份、会话上下文和员工召唤记录。

不负责：直接执行分析方法，也不负责保存其他模块的内部数据。

### 3.5 文件模块

负责用户文件的上传、文件状态、文件归属、文件查看和下载。

支持的文件类型、大小限制、解析失败规则和保留期限在文件模块 PRD 中定义。

不负责：解释文件中的业务含义，也不负责直接生成分析结论。

### 3.6 任务模块

负责把用户请求转化为可追踪的任务，记录任务状态、进度、失败原因和重试状态。

不负责：定义具体统计口径或报告写作风格。

### 3.7 数据分析模块

负责数据分析师相关的分析流程，包括数据检查、数据处理、统计分析、结果解释和分析结果整理。

第一阶段优先支持 Excel/CSV 数据和常用 SPSS 口径分析。

不负责：用户身份管理、文件权限管理和最终报告排版。

### 3.8 定制数据模块

负责按照用户提供的方法、约束和目标生成或调整定制数据。

不负责：替代数据分析模块解释真实数据，也不负责修改用户未授权的原始文件。

### 3.9 职场陪跑模块

负责简历修改、岗位匹配、面试准备、职业规划和职场材料优化等工作。

不负责：数据分析和统计结果判定。

### 3.10 报告模块

负责将分析结果、用户要求和报告模板整理为可阅读、可下载的报告。

报告模块可以被数据分析师或其他允许的虚拟员工召唤。

不负责：擅自改变原始分析结果或统计口径。

### 3.11 员工协作模块

负责记录一个虚拟员工召唤另一个虚拟员工的请求、授权范围、输入内容、输出内容和协作状态。

协作必须发生在当前用户有权访问的会话和任务范围内。

## 4. 核心业务对象

### 4.1 User（用户）

使用应用的人。

关键关系：

- 一个用户可以拥有多个会话。
- 一个用户只能访问自己有权限的数据、文件、任务和结果。

### 4.2 VirtualEmployee（虚拟员工）

用户选择的工作身份，例如数据分析师、定制数据专家、职场陪跑顾问和报告撰写专家。

关键关系：

- 一个虚拟员工可以绑定多个 Skill。
- 一个虚拟员工可以配置允许召唤的其他虚拟员工。
- 虚拟员工不拥有独立的用户数据。

### 4.3 Skill（能力）

一个可复用的业务能力，例如描述统计、相关分析、简历优化或报告撰写。

关键关系：

- 一个 Skill 可以被多个虚拟员工使用。
- Skill 必须有明确的输入、输出、适用条件、异常规则和业务口径。

### 4.4 Conversation（会话）

用户围绕一个工作主题与虚拟员工进行的连续交互空间。

关键关系：

- 一个会话属于一个用户。
- 一个会话有一个当前主虚拟员工。
- 一个会话可以记录多个被召唤的虚拟员工。

### 4.5 Message（消息）

用户、当前虚拟员工或被召唤虚拟员工在会话中的一条输入或输出。

消息可以引用文件、任务、分析结果或报告，但不能越过权限读取其他用户内容。

### 4.6 File（文件）

用户上传的原始文件、中间文件或系统生成的可下载文件。

每个文件必须能够追溯到：

- 所属用户
- 所属会话
- 产生它的任务（如适用）
- 文件类型和当前状态

### 4.7 Job（任务）

一次可追踪的业务处理，例如一次数据分析、一次数据生成或一次报告生成。

任务至少需要有：

- 发起用户
- 所属会话
- 发起员工
- 使用的 Skill
- 输入内容或输入文件
- 当前状态
- 成功结果或失败原因

### 4.8 AnalysisResult（分析结果）

数据分析任务产生的结构化结果、统计表、图表数据和文字解释。

分析结果必须能追溯到原始数据、分析任务、使用的方法和方法版本。

### 4.9 Report（报告）

基于一个或多个分析结果生成的可阅读、可下载成果。

报告不能在没有说明的情况下改变原始分析结果；如有人工修改或格式化，应保留来源关系。

### 4.10 EmployeeInvocation（员工协作记录）

记录一个虚拟员工召唤另一个虚拟员工的过程。

至少包含：召唤方、被召唤方、召唤原因、授权输入、输出结果、状态和所属任务。

## 5. 权限规则

### 5.1 普通用户

普通用户可以：

- 查看和选择被分配的虚拟员工。
- 创建和管理自己的会话。
- 上传、查看和下载自己的文件。
- 发起自己有权限使用的任务。
- 查看自己的分析结果和报告。
- 在允许范围内召唤其他虚拟员工。

普通用户不可以：

- 查看其他用户的会话、文件、任务或结果。
- 修改虚拟员工的系统能力和 Skill 配置。
- 绕过任务权限直接读取其他会话的数据。

### 5.2 管理员

管理员可以：

- 管理用户状态和用户可用范围。
- 配置虚拟员工及其可用 Skill。
- 配置 Skill 的业务说明、版本和适用范围。
- 查看系统运行状态和必要的审计信息。

管理员对用户原始文件和对话内容的访问应遵循最小必要原则，不能因为拥有配置权限就默认获得全部业务数据访问权限。

### 5.3 虚拟员工

虚拟员工不是独立登录用户，不拥有跨用户权限。

虚拟员工只能：

- 在当前用户授权的会话和任务范围内工作。
- 读取当前任务明确提供的文件、消息和中间结果。
- 使用已经绑定且当前允许使用的 Skill。
- 召唤配置中允许协作的其他虚拟员工。

## 6. 数据归属与隔离

- 用户是其会话、消息、文件、任务、分析结果和报告的业务归属者。
- 文件、任务和结果必须能够追溯到用户和会话。
- 不同用户之间默认完全隔离。
- 不同会话之间默认隔离；用户明确引用或复制内容后，才允许在新会话中使用。
- 虚拟员工之间只共享当前任务明确授权的输入和结果。
- 删除或失效的数据不得继续被新任务使用。
- 任务重试不得无记录地覆盖原任务结果。

## 7. 核心数据流

### 7.1 通用工作流

1. 用户登录并选择一个虚拟员工。
2. 系统创建或打开一个属于该用户的会话。
3. 用户发送需求，可同时上传文件。
4. 当前虚拟员工根据自身绑定的 Skill 处理需求。
5. 系统创建任务并记录输入、使用的 Skill 和任务状态。
6. 任务产生中间结果或最终结果。
7. 用户在会话中查看结果，并可以下载允许下载的文件。
8. 如需其他能力，当前虚拟员工在用户授权范围内召唤另一个虚拟员工。
9. 被召唤员工完成工作后，将结果返回当前会话和任务。
10. 当前虚拟员工继续完成任务，或将结果交给报告模块生成报告。

### 7.2 第一阶段数据分析闭环

1. 用户选择“数据分析师”。
2. 用户创建或进入一个分析会话。
3. 用户上传 Excel 或 CSV 文件。
4. 系统确认文件归属、格式和可读取状态。
5. 数据分析师检查数据，并选择适用的分析 Skill。
6. 系统创建分析任务，记录用户、会话、文件、分析方法和任务状态。
7. 分析任务生成统计结果、图表数据和文字解释。
8. 用户在对话框或结果区域查看分析结果。
9. 用户可以下载分析结果或请求生成报告。
10. 如用户请求报告，数据分析师召唤报告撰写专家。
11. 报告撰写专家只使用当前任务授权的分析结果生成报告。
12. 用户查看并下载报告。

## 8. 模块间业务约束

- 模块之间只通过公开业务接口和明确的数据对象沟通。
- 一个模块不得直接修改另一个模块的内部数据。
- 任何跨模块调用都必须能够识别用户、会话和任务归属。
- 分析结果必须注明来源文件、分析方法和任务。
- 报告只能使用已授权的分析结果，不能自行读取未授权原始数据。
- 员工召唤必须有明确的调用方、被调用方和输入范围。
- 任何接口或业务口径变化，都必须同步更新对应模块文档和测试。

## 9. v0.1 范围

本版本先固定产品骨架和第一条核心业务链路：

- 多用户身份和数据隔离原则。
- 虚拟员工列表和员工身份切换。
- Skill 归属和员工能力组合。
- 会话、文件、任务、分析结果和报告之间的关系。
- 数据分析师的 Excel/CSV 分析闭环。
- 数据分析师召唤报告撰写专家的协作方向。

以下内容暂不作为第一阶段实现承诺：

- 复杂的自动意图识别和全局智能分流。
- 多用户之间的数据共享市场。
- 复杂组织架构和多级审批。
- 所有统计方法和所有报告模板一次性覆盖。
- 所有虚拟员工同时上线。

## 10. 待确认事项

以下事项不影响当前总纲成立，但在对应模块 PRD 中必须明确：

- 用户注册、登录和管理员创建用户的具体规则。
- 普通用户可使用哪些虚拟员工。
- Excel/CSV 的文件大小、编码和字段格式限制。
- 分析任务和报告文件的保存期限。
- 失败任务是否允许用户手动重试，以及重试后的结果展示方式。
- 报告首批支持的格式和模板。
- 管理员审计信息的可见范围。
- Skill 和分析方法的版本变更如何影响历史结果。
