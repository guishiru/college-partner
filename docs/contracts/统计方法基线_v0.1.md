# 统计方法基线 v0.1

## 1. 基线目的

本文件定义数据分析师首个闭环使用的 11 个统计方法、标准方法名、输入条件、输出责任和参考来源。

统计计算必须使用确定性的分析引擎。大模型不负责计算统计量，只负责把用户表达转换为结构化参数、发现缺参并生成受结果约束的文字说明。

## 2. 参考来源

本项目采用以下 `V517` 内容作为初始业务基线：

- 统计计算参考：`D:\智数统计\V517\生存模拟数据\validation\test_methods\`
- 方法 Skill 参考：`D:\智数统计\V517\knowledge\analysis\skills\`
- 文字解释参考：`D:\智数统计\V517\knowledge\interpretation\`

注意：

- `D:\智数统计\V517\analysis\service.py` 当前配置指向 `V517\test_methods`，但该目录目前不存在；实际 11 个方法文件位于 `生存模拟数据\validation\test_methods`。迁移前必须先固定真实来源和版本，不能直接把当前路径配置当作可运行基线。
- `V517\knowledge\analysis\SKILL.md` 当前只写了 5 个低风险方法，与本项目 11 方法目标不一致，不能原样作为新项目的完整 Skill 清单。
- `V517\core\config.py` 含硬编码 API 密钥和密钥配置，禁止迁移到新项目或提交 Git。

## 3. 11 个标准方法

| canonical key | 中文名称 | 参考计算文件 | 必要输入 |
|---|---|---|---|
| `descriptive` | 描述统计 | `descriptive_analysis.py` | 至少 1 个数值变量 |
| `frequency` | 频数分析 | `frequency_analysis.py` | 至少 1 个变量 |
| `reliability` | 信度分析 | `reliability_analysis.py` | 至少 2 个同一量表/维度的数值题项 |
| `validity` | 效度分析 | `validity_analysis.py` | 至少 2 个数值题项 |
| `correlation` | 相关分析 | `correlation_analysis.py` | 至少 2 个数值变量 |
| `efa` | 探索性因子分析 | `exploratory_factor_analysis.py` | 至少 2 个数值题项，可选因子数 |
| `cfa` | 验证性因子分析 | `confirmatory_factor_analysis.py` | 因子结构，每个因子至少 2 个题项 |
| `regression` | 线性回归 | `linear_regression.py` | 1 个因变量、至少 1 个自变量 |
| `moderation` | 调节效应分析 | `moderation_analysis.py` | X、Y、M，可选控制变量 |
| `parallel_mediation` | 平行中介效应 | `parallel_mediation_analysis.py` | X、Y、至少 1 个中介变量 |
| `sem` | 结构方程模型 | `sem_analysis.py` | 因子结构和至少 1 条路径 |

`mediation` 可以作为用户输入的别名，但系统内部 canonical key 统一使用 `parallel_mediation`，避免与当前参考代码的命名不一致。

## 4. 方法职责

每个方法必须独立定义以下内容：

- 触发词和用户可理解的名称。
- 必填参数和参数类型。
- 变量数量、变量角色和因子结构要求。
- 数据类型和有效样本要求。
- 缺失值、常数列、重复列、共线和模型不收敛的处理方式。
- 输出表格、关键统计量和有效样本量。
- 对应的文字解释规则。
- 可核对的基准数据和容差。

## 5. 结果约束

- 结构化结果是唯一的统计事实来源。
- 文字说明只能引用结构化结果和批准的解释规则。
- 任何方法失败时必须返回明确失败原因，不得返回看似正常的空结果。
- 结果必须记录方法 canonical key、方法版本、输入文件、变量参数、有效样本量和数据质量报告。
- 历史结果不能因为方法实现升级而被静默重算或覆盖。
