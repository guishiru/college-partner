# 身份、会话与任务契约 v0.1

## 目标

为所有业务模块提供统一的「谁、在哪个会话、做哪个任务」三元身份，使产品总纲第 5、6 章的权限与隔离规则可以被代码强制，而不是依赖调用方自觉。

## 适用范围

本契约约束 `modules/users`、`modules/conversations`、`modules/jobs` 三个模块的对外接口，以及所有跨模块调用必须携带的身份信息。

## 三个业务对象

### User（用户）

- 唯一标识 `user_id`，32 位十六进制。
- `username` 全局唯一，只允许字母、数字、下划线、点、@ 和连字符，长度 3-64。
- `status` 取 `active` 或 `disabled`，停用用户不能通过鉴权。
- 用户由管理员创建，不提供注册接口。

### Session（会话）

- 唯一标识 `session_id`，UUID 格式。
- 每个会话有且只有一个 `user_id`。
- 会话记录当前主虚拟员工 `employee`。
- 会话标识由服务端生成，不接受前端自带的标识。

### Job（任务）

- 唯一标识 `job_id`，32 位十六进制。
- 必须绑定 `user_id`、`session_id`、发起员工 `employee` 和使用的 `skill`。
- 记录输入引用 `input_ref`、状态 `status`、结果引用 `result_ref`、失败原因 `failure_reason` 和尝试次数 `attempts`。
- 状态取 `running`、`succeeded`、`failed`。

## 令牌规则

- 令牌由管理员签发，明文只在签发时返回一次。
- 存储中只保留 SHA-256 摘要，数据库不得包含可直接使用的凭据。
- 令牌可以撤销；撤销后立即失效。
- 调用方通过 `Authorization: Bearer <token>` 传递令牌。

## 归属校验规则

- 任何会话范围内的操作，必须先解析令牌得到用户，再校验会话归属。
- 会话不存在和会话属于他人，必须返回完全相同的错误信息。区分两者会泄露会话归属。
- 文件必须记录 `user_id`，读取时校验；不匹配即拒绝。
- 报告下载必须校验会话归属，不得仅凭标识可猜测性提供保护。

## 任务幂等与重试规则

对应项目约定「任务失败后允许重试，但不能重复生成结果」。

- 每个任务在其会话内有一个幂等键。分析任务的幂等键由文件标识和需求文本共同决定。
- 相同幂等键再次进入时：
  - 已成功：返回原任务和原结果，不重新计算，不生成第二份报告。
  - 执行中：拒绝并返回冲突，避免并发产生两份结果。
  - 已失败：允许重试，任务回到执行中，尝试次数加一。
- 任务结果的完整载荷落盘保存，任务记录中只保存引用，便于重试时原样返回。

## 结果可追溯规则

- 分析结果必须携带 `provenance`，至少包含 `user_id`、`session_id`、`job_id`、来源文件和方法版本。
- 报告只能引用已授权的分析结果，不得自行读取未授权原始数据。

## 跨模块调用约定

- 分析工作流的入口参数中必须包含任务上下文对象，缺少身份的调用在类型层面就不成立。
- `modules/users`、`modules/conversations`、`modules/jobs` 互不依赖，均为叶子模块。
- `modules/web` 是唯一的组装层，负责鉴权、归属校验和任务创建。

## 错误与状态码

| 情况 | 状态码 |
|---|---|
| 缺少令牌、令牌无效、用户已停用 | 401 |
| 会话、文件或任务不属于当前用户 | 403 |
| 同一任务正在执行中 | 409 |
| 参数缺失、文件类型不支持、标识格式非法 | 400 |
| 报告不存在 | 404 |

## 本版本不承诺

- 用户注册、密码登录和令牌自动续期。
- 管理员审计接口。
- 令牌有效期与轮换策略。
- 会话软删除与保留期限。
