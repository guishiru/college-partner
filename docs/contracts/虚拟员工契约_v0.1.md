# 虚拟员工契约 v0.1

## 目标

规定虚拟员工对外暴露什么，以及界面据此渲染什么。对应产品总纲 3.2 和 4.2。

## 员工属性

| 字段 | 说明 |
|---|---|
| `employee_id` | 唯一标识，全局不重复 |
| `name` | 展示名称 |
| `badge` | 侧栏图标上的单字 |
| `description` | 适用场景一句话 |
| `layout` | 工作区布局，见下 |
| `skills` | 可使用的 Skill 标识 |
| `can_invoke` | 允许召唤的其他员工 |
| `available` | 是否已开放使用 |

## 布局

布局是**员工的属性**，不是产品的全局设定。

| 取值 | 形态 | 适用 |
|---|---|---|
| `analysis_split` | 对话 + 结果工作区 | 产出是宽表，且用户需要一边看结果一边提下一个需求 |
| `document_split` | 对话 + 正在起草的文档 | 产出是一份正在成形的文档 |
| `conversation` | 纯对话，没有第二栏 | 回答基本是成段文字，第二栏会一直空着 |

约束：

- 每个员工必须声明一个已定义的布局。
- 界面必须按当前员工声明的布局渲染，不得假定所有员工都用数据分析师那套。
- 新增布局取值必须同时更新本契约、前端样式和测试。

## 状态与能力约束

- 未开放的员工（`available` 为假）不得声明 Skill。
- `can_invoke` 中的员工必须存在。
- 会话只能以已开放的员工创建；未开放或不存在的员工返回 400。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/employees` | 员工清单，含布局。无需鉴权，不含用户数据 |
| POST | `/api/sessions` | 可传 `employee`，缺省为数据分析师；响应返回该员工完整属性 |

## 结果回看

分析结果不能只有最新一次可达。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/jobs/<session_id>` | 该会话的全部任务 |
| GET | `/api/jobs/<session_id>/<job_id>/result` | 读回某次分析落盘的完整结果 |

约束：

- 回看必须校验令牌、会话归属，以及任务确实属于该会话与该用户。
- 任务存在但结果文件缺失返回 404，与无权访问的 403 区分开。
- 重复的相同分析命中任务复用，不得在历史中多出一条，也不得生成第二份报告。

## 已开放的虚拟员工

| 员工 | 布局 | 确定性层 | 判断层留给谁 |
|---|---|---|---|
| 数据分析师 | `analysis_split` | 11 个统计方法，口径固定 | 选哪种分析、怎么解读 |
| PRD撰写 | `document_split` | 15 个必备章节、FR 三件套、验收可观察性、非功能阀值、异常八类覆盖、标注入索引 | 需求还原、范围取舍、优先级 |
| 汇报文档 | `document_split` | 数据自洽、结论先行、标题信息量、层级深度、待补标注 | 是否 MECE、结论对不对、排序逻辑 |

三者共用同一条产品原则：**能机械判定的进代码，需要理解内容的留给大模型和人。**

PRD撰写与汇报文档的分工：PRD 写给研发看，要的是完备；汇报写给要做决定的人看，要的是取舍。两者共用「先出骨架、停下来等确认」和「素材不够就标注不要编」，质检标准不同。

## 写作类接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/documents/skeleton` | 第一轮只出骨架，等用户确认 |
| POST | `/api/documents/draft` | 确认骨架后成稿，过校验回路 |
| POST | `/api/documents/review` | 只审不改，不调模型 |

约束：

- 分派按**会话绑定的员工**决定，不由请求指定——防止用一个会话冒用另一个员工的能力。
- 会话的员工不提供写作能力时返回 400，并提示新建会话。
- 成稿走任务复用：相同员工加相同需求不重复生成。
- 界面上对话栏的标题、提示、欢迎语和快捷词同样随员工变，不得写死成某一个员工的。

## 模型用量

每个任务记录 `model`、`llm_calls`、`input_tokens`、`output_tokens`，**累加不覆盖**（一个任务可能调多次模型）。任务失败同样记账——钱已经花了。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/usage` | 当前用户累计用量，含按 skill 的明细 |
| GET | `/api/usage/<session_id>` | 该会话用量，需校验会话归属 |

限额必须按用户算，按会话算会被新建会话绕过。

## 生成类 Skill 的两道闸门

写作类员工让模型直接产出交付物，成稿前必须过两道：

1. **校验回路**：出稿 → 过该员工的校验器 → 有 error 就把问题清单原样递回让模型重出全文。重写上限默认 2 次，超了把当前稿连同未解决的问题一并交还用户，不得当作合格稿发出。
2. **数字防线**：代码先出事实清单（每条带出处），模型只能用清单里的数；成稿中出现清单外的数字即整稿打回。章节号、条目号、0–12 的小整数、已标注为待补的行不在此列。

骨架阶段不跑校验器——骨架本就不完整，按成稿标准查只会全红。

## 本版本不承诺

- 管理员在界面上增删改虚拟员工（当前注册表在代码中声明）。
- 会话中途切换虚拟员工。
- `document_split` 与 `conversation` 两种布局的完整实现（当前只有声明与渲染分支）。
